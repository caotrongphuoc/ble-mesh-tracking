================================================================================
  BLE Mesh Tracking — Deployment Configuration Template
================================================================================

Fill in every value marked <FILL_IN>, then copy each into the file paths
listed after the "-> " arrow. Only touch the C files listed here; leave
everything else at its default. See docs/00-quickstart.md and
thingsboard/import.md for the full walkthrough.

Values marked [OPTIONAL] have working defaults; skip unless the default
does not fit your setup.

--------------------------------------------------------------------------------
  1. WIFI (used by Gateway, Scanner, Relay — same value in all three)
--------------------------------------------------------------------------------

WIFI_SSID     = <FILL_IN>          e.g. "MyHome_2G"
WIFI_PASSWORD = <FILL_IN>          e.g. "supersecret"

Notes:
  - ESP32 supports 2.4 GHz only. Do NOT paste a 5 GHz SSID.
  - Copy into `BMT_WIFI_SSID` and `BMT_WIFI_PASS` in:
      -> apps/gateway/components/bmt_config/bmt_config.h
      -> apps/scanner/components/bmt_config/bmt_config.h
      -> apps/relay/components/bmt_config/bmt_config.h

--------------------------------------------------------------------------------
  2. THINGSBOARD SERVER (Gateway only)
--------------------------------------------------------------------------------

TB_HOST_IP           = <FILL_IN>   e.g. "192.168.1.50"  (LAN IP of the Docker host)
TB_GATEWAY_TOKEN     = <FILL_IN>   e.g. "AbCdEfGh12345..."  (Devices -> bmt_gateway -> Details -> Copy access token)

TB_CN              = bmt-tb.local  [OPTIONAL — only change if you regen certs with a different hostname]

Notes:
  - Get TB_HOST_IP via `ipconfig` (Windows) or `ip -4 addr` (Linux).
  - Create the gateway device first (see thingsboard/import.md section 4.2),
    then copy the token here.
  - Copy into:
      BMT_TB_IP            -> apps/gateway/components/bmt_config/bmt_config.h
      BMT_TB_GATEWAY_TOKEN -> apps/gateway/components/bmt_config/bmt_config.h
      BMT_TB_CN            -> apps/gateway/components/bmt_config/bmt_config.h  (only if you changed TB_CN)

--------------------------------------------------------------------------------
  3. OTA SERVER (Gateway, Scanner, Relay — usually same host as ThingsBoard)
--------------------------------------------------------------------------------

OTA_SERVER_BASE = <FILL_IN>        e.g. "https://192.168.1.50:8443"  (usually https://<TB_HOST_IP>:8443)

OTA_SERVER_CN = bmt-tb.local       [OPTIONAL — only change if you regen certs with a different hostname]

Notes:
  - Port 8443 is the nginx OTA container from docker-compose.yml.
  - The three URLs derive from OTA_SERVER_BASE:
      Gateway.bin   -> BMT_OTA_GATEWAY_URL  in apps/gateway/components/bmt_config/bmt_config.h
      Scanner.bin   -> BMT_OTA_SCANNER_URL  in apps/scanner/components/bmt_config/bmt_config.h
                       and              in apps/gateway/components/bmt_config/bmt_config.h
      Relay.bin     -> BMT_OTA_RELAY_URL    in apps/relay/components/bmt_config/bmt_config.h
                       and              in apps/gateway/components/bmt_config/bmt_config.h
  - Copy BMT_OTA_SERVER_BASE into apps/gateway/.../bmt_config.h; the three
    per-app URLs are derived from it via preprocessor concatenation.

--------------------------------------------------------------------------------
  4. TAG (per physical tag — one value per device)
--------------------------------------------------------------------------------

TAG_1_MINOR    = 0x0001            (any 16-bit value, unique per tag; keep as 0x0001 for a single tag)
TAG_1_TX_POWER = <FILL_IN>         Measured RSSI at 1 m, e.g. -53 (typical range: -45 to -60)

Additional tags — repeat with unique MINOR:
TAG_2_MINOR    = 0x0002
TAG_2_TX_POWER = <FILL_IN>
TAG_3_MINOR    = 0x0003
TAG_3_TX_POWER = <FILL_IN>

Notes:
  - Flash each tag with a different MINOR — the Scanner uses it as the
    tag identifier.
  - TX_POWER calibration: place the tag exactly 1 m from a scanner, read
    RSSI from the scanner log (`1` command), average a few samples,
    write the number here.
  - Copy into (edit BEFORE building each tag):
      BMT_TAG_MINOR    -> apps/tag/components/bmt_config/bmt_config.h
      BMT_TAG_TX_POWER -> apps/tag/components/bmt_config/bmt_config.h

--------------------------------------------------------------------------------
  5. ZONE MAP (ThingsBoard rule chain — after scanners are flashed)
--------------------------------------------------------------------------------

Fill in one line per scanner. Get the MAC by flashing the scanner, opening
the serial port at 115200, and pressing `1`. Use lowercase, no colons.

SCANNER_1_MAC  = <FILL_IN>         e.g. "86eab91ad6b8"
SCANNER_1_ROOM = <FILL_IN>         e.g. "room_1" (or "living_room", "office", etc.)

SCANNER_2_MAC  = <FILL_IN>
SCANNER_2_ROOM = <FILL_IN>

SCANNER_3_MAC  = <FILL_IN>
SCANNER_3_ROOM = <FILL_IN>

Notes:
  - Where to put these:
      ThingsBoard UI -> Rule chains -> ble_tag_zone_detection ->
      double-click "Apply hysteresis" -> edit the ZONE_MAP object at the
      top of the JS script. Format:
          var ZONE_MAP = {
              "<SCANNER_1_MAC>": "<SCANNER_1_ROOM>",
              "<SCANNER_2_MAC>": "<SCANNER_2_ROOM>",
              "<SCANNER_3_MAC>": "<SCANNER_3_ROOM>"
          };
  - Save the script (top-right check icon), then save the rule chain.
  - Add / remove rows to match the number of scanners actually deployed.

--------------------------------------------------------------------------------
  6. TLS CERTIFICATES (advanced — only if you want your own CA)
--------------------------------------------------------------------------------

The repo ships a dev CA + server cert (CN = SAN = "bmt-tb.local"). Skip
this section unless you need production-grade key material.

CERT_HOSTNAME = bmt-tb.local       [OPTIONAL — the CN the firmware verifies against]

Notes:
  - To regenerate:
      cd thingsboard/tls
      # Edit HOSTNAME inside gen_certs.sh if you changed CERT_HOSTNAME above.
      bash gen_certs.sh
  - Then copy the new `ca.pem`:
      -> apps/gateway/components/bmt_mqtt/ca.pem                (MQTTS CA embedded in Gateway)
      -> components/bmt_ota/ota_ca.pem                          (HTTPS OTA CA shared by Scanner + Relay)
  - Rebuild all firmware after replacing certs.
  - If you kept CERT_HOSTNAME = bmt-tb.local, BMT_TB_CN and
    BMT_OTA_SERVER_CN also stay as "bmt-tb.local" (no code edit needed).

--------------------------------------------------------------------------------
  7. NRF52840 BEACON (advanced — only if using the coin-cell tag variant)
--------------------------------------------------------------------------------

Skip this section unless you build one of:
  - apps/Beacon_ProMicroNrf52840
  - apps/Beacon_XiaoNrf52840

BEACON_TAG_MINOR = 0x0001          Same meaning as TAG_1_MINOR above.

Notes:
  - Fill into src/bmt_config.h of the Beacon app you use.
  - The MCUboot signing key path is already set in sysbuild.conf
    (relative to the repo). Regenerate it for production if desired.
  - See docs/14-nrf52840-beacon.md.

WHERE TO GO NEXT
  1. Fill in every <FILL_IN> in this file for your deployment.
  2. Copy the values into each C header file listed above.
  3. Build and flash each app per docs/00-quickstart.md.
  4. After the scanners are flashed and running, come back to section 5
     (ZONE MAP) with the real MACs.

This file is the template — copy it to `deploy-config.txt` (which is
gitignored) before filling in real WiFi passwords, tokens or IPs, so
your secrets never end up staged for commit.
